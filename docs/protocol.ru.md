# Протокол BM59 — справочник по байтам

*(Английская версия: [protocol.md](protocol.md))*


Всё, что ниже, получено из разбора реального Bluetooth-обмена приложения Beurer с прибором (HCI snoop log на Android) и подтверждено экспериментами на живом устройстве.

## Карта GATT

Сервис Nordic UART (как у тысяч устройств на чипах Nordic), внутри — две пользовательские характеристики и дескриптор:

- `6e400001-...` — сам сервис;
- `6e400002-...` — запись (Write / Write Without Response), **handle 0x0012** — канал «в прибор»;
- `6e400003-...` — индикации (Indicate), **handle 0x0015** — канал «из прибора»;
- `6e400003-...` CCCD — **handle 0x0016** — подписка на индикации.

Полезная нагрузка внутри этого туннеля — **стандартные GATT-характеристики Bluetooth SIG**:

- `0x2A2B` Current Time — 10 байт, идёт в прибор;
- `0x2A35` Blood Pressure Measurement — 18 байт, идёт из прибора.

## Последовательность работы

```
мастер                                   прибор
  |                                          |
  |  connect (LE random, sec-level medium)   |
  |----------------------------------------->|
  |  <---- обмен ключами Just Works ---------|   ~150–350 мс
  |                                          |
  |  ATT WRITE_REQ  handle 0x0016 = 02 00    |
  |----------------------------------------->|   подписка на индикации
  |  <---- ATT WRITE_RSP (0x13) --------------|
  |                                          |
  |  ATT WRITE_CMD  handle 0x0012 = <время>  |
  |----------------------------------------->|   триггер отдачи данных
  |                                          |
  |  <---- ATT INDICATE 0x0015 = <замер> ----|   поток записей
  |  ---- ATT CONFIRMATION (0x1E) ---------->|
  |  <---- ATT INDICATE 0x0015 = <замер> ----|
  |  ---- ATT CONFIRMATION (0x1E) ---------->|
```

Ключевые моменты:

- **CCCD настраивается только через `ATT_WRITE_REQ` (0x12)** и с ожиданием ответа `0x13`. Команда без ответа (`0x52`) в дескриптор CCCD запрещена спецификацией: прибор её игнорирует, и индикации не включаются.
- **Время отправляется без ответа** (`ATT_WRITE_CMD`, 0x52) — так делает приложение.
- **На каждую индикацию нужно отвечать подтверждением** (`ATT_HANDLE_VALUE_CONFIRMATION`, 0x1E). Индикации, в отличие от нотификаций, работают с гарантией доставки: прибор ждёт подтверждения и без него не пришлёт следующую запись, а затем разорвёт связь.
- **Порядок обязателен**: сначала подписка, потом время. Если отправить время без подписки, данные уйдут «в пустоту».

## Пакет времени: Current Time (0x2A2B), 10 байт

| Смещение | Размер | Поле | Формат |
|---|---|---|---|
| 0 | 2 | year | uint16 little-endian |
| 2 | 1 | month | uint8 (1–12) |
| 3 | 1 | day | uint8 (1–31) |
| 4 | 1 | hours | uint8 |
| 5 | 1 | minutes | uint8 |
| 6 | 1 | seconds | uint8 |
| 7 | 1 | day of week | uint8 (1 = понедельник, 7 = воскресенье) |
| 8 | 1 | fractions256 | uint8 (доли секунды, 1/256) |
| 9 | 1 | adjust reason | uint8 (битовая маска) |

Пример — 15 января 2024, 09:12:33, понедельник:

```
E8 07 01 0F 09 0C 21 01 00 00
```

Проверка: `0x07E8` = 2024; `0x01` = январь; `0x0F` = 15; `0x09` = 9 часов; `0x0C` = 12 минут; `0x21` = 33 секунды; `01` = понедельник.

Приложение обновляло этот пакет **раз в минуту** во время сеанса — это видно в логе как серия пакетов с меняющимися минутами и секундами. То есть пакет времени работает и как «отметка присутствия»: прибор ждёт активности.

## Пакет измерения: Blood Pressure Measurement (0x2A35), 18 байт

| Смещение | Размер | Поле (как в наблюдаемых пакетах) | Пояснение |
|---|---|---|---|
| 0 | 1 | flags | `0x16` у BM59 = мм рт. ст. + штамп времени + пульс + статус |
| 1 | 2 | systolic | uint16, мм рт. ст. |
| 3 | 2 | diastolic | uint16, мм рт. ст. |
| 5 | 2 | пульс | uint16 — то самое поле, где спецификация подразумевает среднее артериальное давление |
| 7 | 7 | timestamp | год(2) месяц день час мин сек |
| 14 | 2 | measurement status | uint16 |
| 16 | 2 | reserved / user id | в наблюдаемых пакетах нули |

Байт флагов говорит, в каких единицах значения (мм рт. ст. или кПа), есть ли штамп времени, пульс и статус измерения.

Реальный пакет из дампа:

```
16 80 00 52 00 4A 00 E8 07 01 0F 09 0C 21 57 00 00 00
```

Разбор: `0x0080` = 128 систола, `0x0052` = 82 диастола, `0x004A` = 74 пульс, штамп `2024-01-15 09:12:33`, статус `0x0057`.

Важная деталь: в наблюдаемых пакетах прибор отступает от раскладки по спецификации — пульс приходит в поле 5–6 (там, где спецификация подразумевает среднее артериальное давление), а байты 14–15 несут состояние измерения. Если разбирать пакет «наивно по спецификации», пульс будет прочитан не оттуда.

## Параметры связи, которые требует прибор

- **Тип адреса**: Random Static. В структуре `sockaddr_l2` ядра Linux это тип `2` (`BDADDR_LE_RANDOM`).
- **Уровень безопасности**: Just Works, без MITM. IO capabilities с обеих сторон `NoInputNoOutput`, PIN не запрашивается, ключи не нужны для повторного подключения.
- **Интервал связи**: прибор охотно принимает 7.5–15 мс (для Linux — `conn_min_interval 6`, `conn_max_interval 12`, `conn_latency 0` в настройках HCI).
- **Аппаратный watchdog ~1500 мс**: без осмысленной активности по GATT прибор разрывает связь. Полный опрос таблицы характеристик в это окно не влезает — нужно сразу работать по известным хендлам.

## Что происходит с памятью прибора

Синхронизация с телефоном помечает записи в памяти как отправленные. После этого по воздуху они не отдаются — прибор выдаёт только новые измерения. Проверено: в Bluetooth-логе сеанса с приложением видна ровно одна запись из всей истории.

Практический вывод: если история важна — сначала выгружайте её своим клиентом, и только потом разрешайте приложению синхронизироваться. И делайте резервную копию до любых синхронизаций.
