# Beurer BM59 Unlocked — проект реверс-инжиниринга

*Формальная спецификация протокола по байтам: [docs/specification.ru.md](docs/specification.ru.md)*

*(Английская версия: [README.md](README.md))*

**Реверс-инжиниринг тонометра Beurer BM59: как заставить Linux забрать измерения напрямую, без приложения и без телефона.**

Тонометр Beurer BM59 умеет отдавать историю измерений только своему приложению — через Bluetooth Low Energy, в зашифрованном виде, с закрытым протоколом. Мне это не понравилось: прибор стоит на столе, рядом стоит сервер, а данные всё равно идут через чужой софт.

Я вскрыл протокол. Теперь измерения забирает мой собственный код на Linux — по воздуху, без приложения, без аккаунтов и без облака.

Всё, что ниже — не теория: байты сняты с реального Bluetooth-лога, проверены на живом приборе и сходятся до последнего бита.

---

## Что внутри протокола (кратко)

Прибор Beurer BM59 построен на чипе Nordic и туннелирует **стандартные GATT-характеристики Bluetooth SIG** через сервис Nordic UART. Ничего своего Beurer не изобретал — и это ключ ко всему.

- **Характеристика `...6e400002...` (write, handle `0x0012`)** — вход. Сюда летит пакет текущего времени.
- **Характеристика `...6e400003...` (indicate, handle `0x0015`)** — выход. Отсюда прибор отдаёт измерения.
- **Дескриптор CCCD, handle `0x0016`** — «подписка» на выход.

Порядок ровно такой, как делает приложение-телефон:

1. Подключиться к прибору.
2. Записать `02 00` в CCCD (`0x0016`) — **именно запросом с ответом** (`ATT_WRITE_REQ`, опкод `0x12`). Запись без ответа (`0x52`) прибор молча выбрасывает: спецификация Bluetooth прямо запрещает настраивать CCCD командой без подтверждения.
3. Записать 10 байт текущего времени в `0x0012` — уже без ответа (`ATT_WRITE_CMD`).
4. Принимать входящие индикации (`0x1D`) из `0x0015` и на каждую отвечать подтверждением (`0x1E`), иначе прибор замолкает.

### Пакет времени — это стандартный `Current Time` (0x2A2B)

```
E8 07 | 01 | 0F | 09 | 0C | 21 | 01 | 00 | 00
  |     |    |    |    |    |    |    └────┴── доли секунды, причина смены времени
  |     |    |    |    |    |    └── день недели (1 = понедельник)
  |     |    |    |    |    └── секунды
  |     |    |    |    └── минуты
  |     |    |    └── часы
  |     |    └── день месяца
  |     └── месяц
  └── год (little-endian: 0x07E8 = 2024)
```

### Ответ прибора — стандартный `Blood Pressure Measurement` (0x2A35)

```
16 | 80 00 | 52 00 | 4A 00 | E8 07 01 0F 09 0C 21 | 57 00 | 00 00 00
 |     |       |       |            |                 |        └── статус
 |     |       |       |            |                 └── пульс-статус
 |     |       |       |            └── штамп измерения: 2024-01-15 09:12:33
 |     |       |       └── пульс
 |     |       └── диастола
 |     └── систола
 └── флаги (единицы мм рт. ст., есть штамп времени и пульс)
```

Прибор начинает отдавать записи **сам**, как только включены индикации и прилетел пакет времени. Никаких «дай мне историю» — просто поток.

## Почему это было нетривиально

Три вещи делают задачу неочевидной, и каждая стоила мне вечера:

**1. Аппаратный watchdog на 1500 мс.** Если за полторы секунды прибор не получил осмысленной активности по GATT — он разрывает связь. Никаких «сначала неспешно обсудим сервисы».

**2. Классический опрос GATT в него не влезает.** BlueZ, прежде чем отдать управление, обязан вычитать всю таблицу характеристик (`ServicesResolved`). На медленном канале (USB-донгл, проброшенный в виртуальную машину) это занимает 2.5–3.5 секунды — прибор уходит раньше. Android в это окно попадал только потому, что у него уже был локальный кэш характеристик и он бил сразу по хендлам, не тратя время на опрос.

**3. Тип адреса.** Прибор вещает как **случайный статический адрес** (Random Static). Если подключаться «по строке» MAC без указания типа, стек стучится как к публичному устройству — прибор просто игнорирует.

Решения, которые в сумме дали связь:

- подключаться напрямую, минуя полный опрос GATT — сразу по хендлам (через `gatttool` или собственный ATT-сокет);
- тип адреса — **random**;
- уровень безопасности — **medium** (Just Works): шифрование поднимается на лету, ключи не нужны, PIN не спрашивают;
- после подключения — пауза ~250–350 мс, дать ядру завершить обмен ключами, и только потом первая запись;
- на каждую индикацию отвечать подтверждением `0x1E`.

## Как повторить

Нужен Linux с Bluetooth-адаптером и правами root. Прибор — в режиме передачи (кнопка удержана ~3 секунды, значок Bluetooth мигает).

Самый быстрый путь — интерактивный `gatttool`:

```bash
hciconfig hci0 reset

gatttool -t random -b <MAC> -l medium -I
# далее в интерактивном режиме, без пауз больше пары десятых секунды:
connect
char-write-req 0x0016 0200
char-write-cmd 0x0012 <10 байт времени>
# и слушать: Indication handle = 0x0015 value: 16 ...
```

Обратите внимание: `char-write-req` (с ответом) для CCCD и `char-write-cmd` (без ответа) для времени. Если перепутать — прибор молча ничего не сделает.

Более надёжный путь (и то, чем я в итоге пользуюсь) — собственный клиент на сокете ядра Linux: `AF_BLUETOOTH` + `BTPROTO_L2CAP`, фиксированный канал ATT (CID 4), структура `sockaddr_l2` с типом адреса `2` (LE random) и уровнем безопасности medium. Там под вашим контролем все тайминги до миллисекунд, и нет зависимости от утилит.

## Что было вскрыто и как

Протокол снят не угадыванием и не перебором, а честным анализом трафика:

1. На Android был включён HCI snoop log — система пишет весь Bluetooth-обмен в файл.
2. Приложение синхронизировали с прибором, получили дамп.
3. Дамп разобран вручную: пакеты ATT разложены по опкодам, хендлам и значениям.
4. Байты сверены со спецификацией Bluetooth SIG — оказалось, что внутри туннеля Nordic лежат ровно стандартные структуры `0x2A2B` и `0x2A35`.
5. Гипотеза о «своём протоколе Beurer» была отброшена как неверная: структура совпала до последнего поля, включая день недели и штамп времени.

Отдельная находка: **синхронизация с телефоном помечает записи в памяти прибора как отправленные**, и по воздуху они больше не отдаются. Если хотите сохранить историю — сначала забирайте её сами, и только потом подключайте приложение.
